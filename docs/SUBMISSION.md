# Submission checklist

## Deadlines

| Hack | Final submission |
| --- | --- |
| MLH Solana Hackathon | Sunday 8 November, 11:45 AM ET (7:45 PM Nairobi) |

Confirm both on the event pages. Neither hack's page said whether one project may be entered in both, or whether prior work is allowed, so check the rules or ask the programme managers before you submit.

## Required for every entry

- [ ] Public repository with this README and working setup instructions
- [ ] Program deployed (devnet is enough for Encode's tracks)
- [ ] A working demo link or a clear way to run it locally
- [ ] Demo video of 2 to 4 minutes (see scripts/record-demo.md)
- [ ] Written explanation of how Solana powers the project (docs/SOLANA.md)

## Encode: Aurora Intents challenge

- [ ] One real deposit through the Swap API, shown live in the video, not mocked
- [ ] Correct refund handling visible in the code and described in docs/AURORA.md
- [ ] A short note on which chains you tested as the source

## Encode: Best Use of x402 on Solana

- [ ] The full flow in the demo: payment request, verification and settlement on Solana, resource delivered
- [ ] Failed payments handled and documented (the receipts page shows refusals)
- [ ] Explain the smart wallet approach: the payment is a program instruction, not a plain token transfer

## Encode: Best Consumer App on Solana

- [ ] A clear audience and problem: people who let AI agents spend money
- [ ] Onboarding that works end to end for a first-time user
